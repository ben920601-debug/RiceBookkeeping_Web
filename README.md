# 記帳米粒 ｜ 監控台說明文件

---

## 一、架構總覽

監控台從原本「一份 `index.html` 塞所有頁面、靠 JS 切換顯示」的單頁應用（SPA）架構，
拆成**六個獨立檔案**，各自是一個真實存在的 HTML 檔案：

```
shared.js       — 所有頁面共用的邏輯（session、API、圖表、導覽列、守門機制）
index.html      — 入口頁：LIFF 登入 + 監控首頁
manage.html     — 明細查詢
orders.html     — 團單核銷（群組限定）
trips.html      — 旅行規劃
finance.html    — 理財工具：繳費／存錢／支付方式（個人限定）
```

### 為什麼要拆

1. **安全**：以前不管某功能有沒有開放，程式碼都跟著 `index.html` 一起下載到每個人手機裡，打開瀏覽器開發工具就看得到。拆開後，沒有實際點進某頁面，該頁面的程式碼根本不會被下載。
2. **可維護性**：改旅行規劃的邏輯不會不小心影響到理財工具，各頁面互相獨立。

### 跨頁面怎麼共用登入狀態

不是用網址參數，而是用瀏覽器的 **`sessionStorage`**（同一個分頁內有效，分頁關掉就清除，不會留下明碼痕跡）。使用者在 `index.html` 完成 LIFF 登入、選好個人／群組模式後，`saveSession()` 把結果寫進 `sessionStorage`；其他頁面一開啟就用 `requireSession()` 讀這份資料，沒有的話直接導回 `index.html` 重新走登入流程。

```js
// shared.js
saveSession(mode, targetId, displayName, pictureUrl)   // 寫入
getSession()                                            // 讀取（回傳 {verified, mode, targetId, isGroup, ...}）
requireSession()                                         // 子頁面開頭呼叫，沒登入就導回首頁
```

## 二、頁面功能說明

### `index.html`（監控首頁）

- 個人版：本月收支總和、收入、現金支出、支付工具支出（使用率最高者）、支出與支付工具比例圖、當日即時明細
- 群組版：本月群組總開銷、一般支出＋團購訂單、支出與收入分類比例圖、本月即時明細
- 右上角「⚖️ 校正」按鈕（個人限定）：輸入實際擁有的金額，系統自動算出差異並記一筆「餘額校正」的收入或支出

**重要機制**：進站時會先檢查 `sessionStorage` 有沒有已登入的 session——**有**就直接顯示首頁（不重新跑 LIFF）；**沒有**才跑完整登入流程。這是為了讓「返回首頁」不會每次都像重新登入一次。

### `manage.html`（明細查詢）

依日期區間、收支類型、支付方式（個人限定篩選項）查詢，選定支付方式後上方會顯示該類型總和。記錄可線上編輯／刪除。群組版額外顯示歷史墊付貢獻排行圖。

### `orders.html`（團單核銷，群組限定）

歷史揪團訂單列表，可修改墊付人、新增／編輯／刪除付款人品項，成員選擇一律用下拉選單（呼叫 LINE 官方 API 抓真實成員清單），避免手動輸入名字打錯字導致核銷對不上人。

### `trips.html`（旅行規劃）

查看、新增、編輯、刪除旅行與行程地點。與 LINE 對話裡的「旅行修改 單號」共用同一份資料。

### `finance.html`（理財工具，個人限定）

三個子區塊：💳 繳費管理、🐷 存錢筒、💰 支付方式，各自都有新增表單 + 清單 + 編輯/刪除。

## 三、安全與守門機制

### 1. 功能狀態（`feature_switches`）

每個功能（`trips_dashboard` / `orders_dashboard` / `finance_dashboard`）在中控台可以設定四種狀態：

| 狀態 | 監控台行為 |
|---|---|
| `normal` | 正常顯示，可自由進入 |
| `beta` | 圖示右上角有 Beta 小標籤，點進去前要求輸入密碼 |
| `maintenance` | 圖示右上角有「維護」標籤，點進去前要求輸入密碼 |
| `hidden` | **整顆圖示直接消失**，直接打網址也會被導回首頁；LINE 對話端也會完全裝作沒看到觸發關鍵字 |

密碼與**中控台登入密碼共用同一組**，驗證通過後當次瀏覽（`sessionStorage`）不用重複輸入。

### 2. 監控台總開關與跑馬燈

中控台可以整個關閉監控台（顯示維護畫面）、設定跑馬燈公告文字/顏色/速度。維護畫面下方有密碼欄位，管理者/測試人員可以提前繞過。每 30 秒背景輪詢一次，設定變更不用使用者手動重新整理就會生效。

## 四、部署方式

六個檔案（`shared.js` + 五個 `.html`）放在**同一個資料夾**，直接覆蓋部署即可，不需要建置流程（沒有 npm build 這類步驟，純靜態檔案）。

### LIFF 設定

Endpoint URL 只需要指向 `index.html`，因為使用者永遠是先進首頁完成登入，其他頁面是站內導覽過去的，不是重新走 LIFF 流程。

### 快取（⚠️ 重要）

LINE 內建瀏覽器對靜態檔案的快取非常頑固，本專案用了兩層機制強制繞過：

1. **每個 HTML 檔案**：開頭有一段自動幫網址加上 `?v=時間戳記` 的腳本，網址不同瀏覽器就不會用舊快取
2. **`shared.js`**：不是用固定的 `<script src="shared.js">`，而是用 `document.write()` 動態產生帶時間戳記的網址（`shared.js?v=...`），因為外部 JS 檔案不會跟著 HTML 頁面的網址一起變動，需要額外處理才會強制重新下載

若之後修改 `shared.js` 卻感覺「怎麼改都沒用」，先確認這層有沒有正常運作，而不是急著懷疑邏輯寫錯。

## 五、常見問題排查

| 症狀 | 常見原因 |
|---|---|
| 整頁空白，Console 沒有任何錯誤訊息 | HTML 結構壞了（例如 `<style>` 沒有正確用 `</style>` 閉合），不會產生 JS 錯誤，但瀏覽器會誤判後面內容 |
| 登入完成後卡在驗證畫面，要重整才會過 | 通常是某個 API 呼叫卡住、沒有逾時機制，導致後續流程永遠不會被觸發 |
| 改了 `shared.js` 但畫面行為完全沒變 | 大機率是快取問題，確認 `shared.js` 有沒有透過 `document.write` 帶時間戳記載入 |
| 導覽列圖示該藏的沒藏、或該顯示的沒顯示 | 檢查「畫導覽列」跟「取得功能狀態」這兩件事的執行順序，一定要先等資料回來才畫 |
| 關閉某功能後，其他圖示留白沒有自動補滿 | 導覽列容器要用 `flex`（自動依可見項目數量分配寬度），不能用固定的 `grid-cols-N` |

## 六、技術重點摘要

- **前端框架**：無框架，純 HTML + Tailwind CDN（`@tailwindcss/browser`）+ Chart.js（僅 `index.html`/`manage.html` 需要）
- **狀態管理**：`sessionStorage`（跨頁面共用登入狀態），不使用 `localStorage`（分頁關閉即清除，較不留下痕跡）
- **API 逾時保護**：所有 API 呼叫（`apiFetch`）都有 10 秒逾時機制，避免任何一支 API 卡住就讓整頁永遠沒反應
- **保險機制**：導覽列顯示邏輯有雙重保障——正常情況判斷完就顯示，萬一邏輯出錯，最慢 1.5 秒後也會強制顯示，確保使用者不會被卡在無法點擊任何東西的畫面
